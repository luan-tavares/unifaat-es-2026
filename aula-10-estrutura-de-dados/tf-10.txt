CONTEXTO

Na Aula 10 vimos as estruturas de dados (lista, tupla, dicionario, pilha, fila, arvore e grafo) e, para cada uma, a analise de LEITURA x ESCRITA: ler e escrever tem custos diferentes, e ganhar em uma costuma significar perder na outra. Contamos esse custo em PASSOS. Vimos tambem que o Git e um grafo: cada commit e um no, a aresta e o ponteiro para o commit pai, a branch e so um ponteiro para um commit, e o merge e um commit com DOIS pais.

Agora e a vez de voces construirem um MiniGit: uma classe que guarda commits e branches usando as estruturas da aula, e que CONTA os passos de cada operacao. O MiniGit nao mexe em arquivos nem em conteudo: so no historico (commits, pais e branches). O objetivo e ver, com numeros, o que e barato e o que e caro.

Estruturas que voces vao usar: dicionario (commit -> pais, commit -> mensagem, branch -> commit), lista (os pais de cada commit), tupla (o que os metodos devolvem) e fila (para percorrer o historico).

Criar a classe MiniGit (parte 1: commits) Crie o arquivo minigit.py com a classe MiniGit. Detalhes:

- Estado privado, declarado em __slots__: um dicionario de pais (commit -> lista dos pais), um dicionario de mensagens (commit -> mensagem), um dicionario de branches (branch -> commit para onde ela aponta), o nome da branch atual, um contador para gerar os identificadores e o numero de passos da ultima operacao;
- O construtor nao recebe nada. O repositorio nasce vazio, na branch "main", que ainda nao aponta para nenhum commit;
- Os identificadores dos commits sao gerados em ordem: "c1", "c2", "c3"...;
- commitar(mensagem): cria um commit novo, filho do commit para onde a branch atual aponta (o primeiro commit nao tem pai), move o ponteiro da branch atual para ele e devolve o identificador. Levanta ValueError se a mensagem for vazia;
- mensagem(commit): devolve a mensagem do commit. Levanta ValueError se o commit nao existe;
- pais(commit): devolve os pais do commit como TUPLA (nunca a lista interna, para ninguem estragar o historico por fora). Levanta ValueError se o commit nao existe;
- passos: uma property so de leitura (sem setter) que devolve quantos passos a ULTIMA operacao gastou. Fora da classe, git.passos = 5 tem que dar erro.

Commit:

git add .
git commit -m "Cria o MiniGit com commitar, mensagem e pais"

Criar a classe MiniGit (parte 2: branches e merge) No mesmo arquivo, acrescente:

- criar_branch(nome): cria a branch apontando para o commit da branch atual. Levanta ValueError se a branch ja existe ou se ainda nao ha commits;
- trocar_branch(nome): passa a branch atual a ser a indicada. Levanta ValueError se ela nao existe;
- mesclar(nome): cria, na branch atual, um commit com DOIS pais (o commit da branch atual e o commit da branch indicada), com a mensagem "merge de <nome>", move o ponteiro da branch atual e devolve o identificador. Levanta ValueError se a branch nao existe ou se for a propria branch atual;
- branch_atual: property so de leitura.

Commit:

git add .
git commit -m "Acrescenta branches e merge"

Criar a classe MiniGit (parte 3: leitura do historico) No mesmo arquivo, acrescente:

- log(): devolve, como tupla, os identificadores de todos os commits alcancaveis a partir do commit da branch atual, seguindo os pais. Cada commit aparece uma vez so. Use uma FILA (collections.deque): coloque o commit da ponta na fila e, enquanto a fila nao estiver vazia, tire o primeiro, anote-o (se ainda nao anotado) e coloque os pais dele no fim da fila. Se nao ha commits, devolve uma tupla vazia;
- buscar(texto): devolve o identificador do primeiro commit, na ordem de criacao, cuja mensagem contem o texto; se nenhum tem, devolve None;
- merges(): devolve, como tupla, os commits que tem mais de um pai, na ordem de criacao.

Commit:

git add .
git commit -m "Acrescenta log, buscar e merges"

CONTAR OS PASSOS (o coracao do trabalho)

Cada operacao publica da classe, ao terminar, guarda no estado privado quantos passos gastou, e a property passos devolve esse numero. A contagem e FIXA, assim:

Escrita:
- commitar: 2 passos (1 por criar o commit + 1 por mover o ponteiro da branch). O mesmo vale para mesclar;
- criar_branch: 1 passo (1 ponteiro criado);
- trocar_branch: 1 passo (1 ponteiro movido).

Leitura:
- mensagem e pais: 1 passo (vai direto na chave do dicionario);
- log: 1 passo por commit visitado (o numero de commits da tupla devolvida; 0 se nao ha commits);
- buscar: 1 passo por commit olhado, ate achar (ou todos, se nao achar);
- merges: 1 passo por commit existente.

Numere os passos no codigo, nao em um print: quem usa a classe le git.passos depois de chamar o metodo.

Commit (junto com o que for ajustado na contagem):

git add .
git commit -m "Conta os passos de cada operacao"

def tentar(acao):

Roteiro de teste (monta a mesma historia do slide da aula: dois commits na main, uma branch feature criada no segundo, um commit novo em cada branch e o merge):

git = MiniGit()
git.commitar("primeiro commit")
print(git.passos)
git.commitar("segundo commit")
git.criar_branch("feature")
print(git.passos)
git.commitar("terceiro commit")
git.trocar_branch("feature")
git.commitar("quarto commit")
git.trocar_branch("main")
git.mesclar("feature")
print(git.pais("c5"))
print(git.log(), git.passos)
print(git.mensagem("c3"), git.passos)
print(git.buscar("quarto"), git.passos)
print(git.merges())
git.trocar_branch("feature")
print(git.log(), git.passos)
git.trocar_branch("main")

As quatro tentativas que precisam FALHAR e imprimir o erro (use a funcao tentar, com lambda):

REGRAS

Unico import permitido: deque, de collections (from collections import deque). Nada de dataclasses, typing, copy ou outros.
Nenhum atributo publico solto: todo o estado do MiniGit e privado (__), declarado em __slots__ e acessado por property ou metodo.
Nenhum metodo devolve uma lista ou dicionario interno: devolva tuplas (ou copias).
Nada de else (nem elif): usar retorno antecipado, continue e valor padrao.
Nomes sem abreviacoes (mensagem, e nao msg; identificador, e nao id).
A classe e cada metodo devem ter comentarios explicando, com as proprias palavras, o que fazem e quantos passos gastam.
Pelo menos 5 commits no Git, na ordem do roteiro.
A pasta .venv nao pode aparecer no repositorio.
O repositorio no GitHub deve estar Public, pra que o codigo possa ser conferido pelo link enviado.
Trabalho individual: codigos identicos entre colegas serao considerados copia e zerados para todos os envolvidos.
Todo o trabalho deve ser feito dentro do ambiente Linux do WSL.
