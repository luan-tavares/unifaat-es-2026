O kernel é o núcleo: quem fala com o hardware

  • Processos: quem usa o processador e por quanto tempo
  • Memória: a parte de cada programa, isolada das outras
  • Arquivos: o disco em diretórios, e quem pode ler ou alterar
  • Dispositivos: teclado, disco, rede e vídeo, pelos drivers
programacat arquivo.txtpede
kernelconfere e decidepermissão, memória
discolê os bytes
conteúdo na tela
devolve ao programa
# chamada de sistema (system call)
o cat não toca o disco: ele pede ao kernel
# o árbitro
o kernel confere a permissão e separa a memória de cada programa
# só o kernel fala com o hardware
ele lê o arquivo no disco por meio do driver
# a resposta volta
o conteúdo chega ao programa, que mostra na tela

Todo o resto pede ao kernel, e o kernel decide.

Lendo o ls -la: a notação rwx

-rwxr-xr--1luandev1234Nov 25 10:00deploy.sh
drwxr-xr-x3luanluan4096projetos
# tipo
- arquivo, d diretório, l link
# dono (user)
rwx: ler (read), escrever (write) e executar (execute)
# grupo
r-x: ler e executar, não escrever (o - é "não tem")
# todo o resto (others)
r--: só ler
# usuário dono
quem manda no arquivo
# grupo dono
e o grupo a que vale o segundo trio
# lendo a linha inteira
arquivo; o dono luan faz tudo, o grupo dev lê e executa, o resto só lê

Em diretório: r lista, w cria e apaga, x entra (cd).

terminal
# r=4 w=2 x=1 (é o binário da Aula 03: rwx = 111 = 7)
$ chmod 755 deploy.sh
$ chmod 644 notas.txt
$ chmod 600 ~/.ssh/id_ed25519
$ sudo chown luan:dev deploy.sh
# cada letra é um bit
rwx = 4 + 2 + 1 = 7; um número por trio: dono, grupo, outros
# 755
padrão de scripts e diretórios: o dono faz tudo, os outros leem e executam
# 644
padrão de arquivos comuns: só o dono edita
# 600
só o dono: é o que a chave SSH privada exige (Aula 05)
# chown usuário:grupo
troca o dono e o grupo; exige sudo. Evite chmod -R 777

Deem só a permissão que é necessária, a quem precisa.
